# МедКонспект — полностью статическая версия

Учебная платформа для медицинского колледжа со структурой:

```text
Учебное заведение → Курс → Предмет → Раздел (необязательно) → Тема
```

Сайт **не требует сервера, базы данных, Cloudflare Worker, Next.js или React в production**. После сборки получается обычная папка `dist/` с HTML, CSS, JavaScript и изображениями. Её можно бесплатно размещать на GitHub Pages и других статических хостингах.

## Что уже работает

- Медицинский колледж имени Башларова;
- направление «Лечебное дело» над выбором курса, без отдельного клика;
- 1–4 курсы;
- 8 текущих тем по Терапии;
- Терапия → сразу список тем, без отдельной страницы «Пульмонология»;
- необязательные разделы для будущих предметов;
- полнотекстовый поиск прямо в браузере;
- сохранение места чтения каждой темы отдельно через `localStorage`;
- мобильная и desktop-вёрстка;
- SEO-метаданные, `sitemap.xml`, `robots.txt`, Open Graph и JSON-LD для тем;
- автоматическая генерация страниц из Markdown.

## Требования

Нужен только Node.js 20 или новее.

В проекте нет npm-зависимостей, поэтому установка практически мгновенная.

```bash
npm ci
```

## Сборка

```bash
npm run build
```

Готовый сайт появится здесь:

```text
dist/
```

Именно содержимое `dist/` является полностью статическим сайтом.

## Локальный просмотр

```bash
npm run dev
```

После этого откройте:

```text
http://localhost:3000
```

## Автоматическая проверка

```bash
npm test
```

Тесты проверяют основные страницы, отсутствие лишнего уровня «Пульмонология», подпись «Лечебное дело», локальный прогресс чтения и статический поиск.

## Где лежат материалы

```text
content/
└── colleges/
    └── bashlarova/
        ├── college.json
        └── topics/
            ├── 01-bronchitis.md
            ├── 02-pneumonia.md
            └── ...
```

Одна тема = один Markdown-файл.

После добавления или изменения материала достаточно снова выполнить:

```bash
npm run build
```

Страницы, навигация, поиск и sitemap пересоберутся автоматически.

Подробная инструкция: [CONTENT_GUIDE.md](./CONTENT_GUIDE.md).

## Бесплатная публикация на GitHub Pages

В проект уже добавлен файл:

```text
.github/workflows/deploy-pages.yml
```

Он автоматически собирает и публикует сайт.

1. Создайте обычный репозиторий GitHub.
2. Загрузите туда **содержимое этого проекта**, а не только ZIP.
3. Убедитесь, что основная ветка называется `main`.
4. В GitHub откройте **Settings → Pages**.
5. В разделе Source выберите **GitHub Actions**.
6. После push в `main` workflow соберёт `dist/` и опубликует сайт.

Workflow сам учитывает адрес вида:

```text
https://username.github.io/repository-name/
```

поэтому ссылки, CSS, поиск и вложенные страницы не ломаются даже если сайт находится не в корне домена.

## Свой домен

Позже можно подключить свой домен через GitHub Pages.

Чтобы сборка автоматически создавала правильные canonical URL и `CNAME`, добавьте в репозитории GitHub переменную Actions:

```text
CUSTOM_DOMAIN
```

со значением вашего домена, например:

```text
medkonspekt.ru
```

После этого workflow будет собирать сайт уже для собственного домена без `/repository-name/` в адресах.

## Основные каталоги

```text
content/                 учебные материалы
public/                  изображения и favicon
assets/styles.css        дизайн сайта
scripts/build-static.mjs генератор статических HTML-страниц
scripts/serve.mjs        простой локальный сервер только для просмотра
.github/workflows/       автоматическая публикация GitHub Pages
dist/                    готовый статический сайт после сборки
```

Для обычного наполнения сайта программный код менять не требуется.
